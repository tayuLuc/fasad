# `fuzz/` — фазз-таргеты (вне workspace, намеренно)

Требование issue #50 («фаззер для реврайтера»), закрытие замечания **Н4** ревью
#54. Один таргет — [`fuzz_targets/f0_rewrite.rs`](fuzz_targets/f0_rewrite.rs):
потоковый реврайтер `guard_vault::rewriter`, обе грамматики (`LABEL`,
`F0_INLINE`). Вход — один `&[u8]`: первые до четырёх байтов играют байты реза,
остальное — сам поток (двухаргументная форма `fuzz_target!` в libfuzzer-sys
0.4.13 требует `#[derive(Arbitrary)]`, derive-фичу тянуть не стали).

## Почему вне workspace

`[workspace] exclude = ["fuzz"]` в корневом `Cargo.toml`. Таргет линкует
`libfuzzer-sys` (значит `cc`, `arbitrary` и фаззер-рантайм), а `just lint`,
`just test` и `just deny` обязаны работать на раннере, где `cargo-fuzz` не
стоит. Отсюда границы доверия, которые нельзя притворять гейтом:

1. CI таргет **не собирает и не гоняет** — регрессии по нему нет;
2. зависимости таргета **не попадают** в root `Cargo.lock` и в аудит
   `cargo deny` (при переносе фазза в CI их надо досматривать отдельно);
3. corpus в репозитории **нет**: осознанно, #50 допускает таргет без сида, а
   приманки грамматик (`[[F0#`, `[CLIENT_PERSON_1]`) фаззер находит сам по
   coverage-фидбеку; разбор — в шапке таргета;
4. сам таргет проверен только `cargo check` (см. «Честный статус») — утверждать,
   что он «что-то фаззит», до первого прогона нельзя.

## Чем заменено покрытие в CI

Инварианты таргета продублированы живыми тестами в
`crates/guard-vault/src/rewriter.rs`, и они гоняются на всех трёх ОС матрицы:

| инвариант | тест | промер |
|---|---|---|
| `Unknown`-резолвер ⇒ выдача == вход, при любом разрезе | `random_bytes_pass_verbatim_under_any_split` | 4000 итераций × 2 грамматики |
| подмена не раздувает выдачу | `substitution_never_grows_output` | 2000 итераций × 2 грамматики |

## Как гонять

```sh
cargo install cargo-fuzz            # разово, на машину разработчика
cargo +nightly fuzz run f0_rewrite -- -max_total_time=600
```

`cargo check` без `cargo-fuzz` тоже кое-что доказывает (таргет собирается):

```sh
cargo check --manifest-path fuzz/Cargo.toml
```

Что делать с находкой: контрпример падает в `fuzz/artifacts/f0_rewrite/crash-*`,
минимизируется `cargo fuzz minimize f0_rewrite <crash>`, сид переезжает в
`fuzz/corpus/f0_rewrite/` (тогда и пункт 3 выше перестаёт быть правдой — README
обязан обновиться вместе с ним).

## Честный статус этого коммита

Таргет **проверен только сборкой** (`cargo check --manifest-path
fuzz/Cargo.toml`), не прогоном: `cargo-fuzz` на машине разработки не установлен,
ночной фазс-ран в CI этого шага нет. Первый реальный прогон — задача шага 6–8,
отметка об этом есть в рапорте к #50 и в тексте коммита.
