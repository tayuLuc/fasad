# fasad — правила workspace

Проект: локальный AI-гард (стендэлон-демон, Rust, оффлайн, <2 ГБ).
Полная спецификация: [docs/SPEC.md](docs/SPEC.md). Источник фактуры: транскрипт
диалога с LLM-ассистентом ([docs/source-note.md](docs/source-note.md), носитель удалён).

## Дисциплина фактов (обязательно)

1. SPEC.md — **вторичный источник** (LLM-транскрипт). Любое число, версия, имя
   модели/крейта из него — `[claim]`, пока не подтверждён промером первички
   (HF-карточка, crates.io, регистр GitHub Actions, дока ORT).
2. Перед тем как написать код по §7 (зависимости) — выполнить §11 (верификация) и
   записать результат в `docs/dep-verify.md`. Код с непроверенными версиями не мержится.
3. Чексуммы РФ/ЕС — только по таблицам `docs/dep-verify-algorithms.md` (первичка
   промерена 18.10; 4 утверждения транскрипта опровергнуты, в т.ч. ОГРНИП=mod13,
   RU-IBAN существует, «Мир» весь 22xxxx). Эталонные векторы переносить в тесты
   таблицами; запрещено вычислять ожидаемое той же функцией, что проверяется.
   Формула и структура ОГРН/ОГРНИП закрыты 19.10 первичкой (п.7 Приказа Минфина
   от 30.10.2017 № 165н) и реализованы как структурное вето — см. §4.
   Не закрыто: полная таблица счетов (носитель — PDF 809-П, 579-П отменён с
   01.01.2023) — см. §11 п.6 и §7a.
4. Метрика recall (§5 п.7) — только по нашему golden-набору `data/golden/`, **N≥150**
   (промер Wilson CI: при N=50 планка 98 % статистически непроверяема); чужие «99 %»
   в README не цитировать как наши.

## Инженерные инварианты (из SPEC, не обсуждается без причины)

- Fail-Closed: ошибка/таймаут детектора = запрос наружу не уходит. Никогда fail-open.
- Все буферы с оригиналами ПДн: `ZeroizeOnDrop` + mlock/VirtualLock. Никаких `String`
  с секретами в логах, Debug-вывод только `[REDACTED]`.
- Приоритет детерминированного валидатора (чексумма) = 1.0, нейросеть не понижает.
- Порог экстрактора низко (0.20–0.25): FN фатален, FP дёшев благодаря обратимости.
- Никакой телеметрии, никаких сетевых вызовов кроме явного `X-Upstream-URL`.
- `panic = "unwind"` (не abort): паника одного запроса не валит демон.

## Порядок работы агента

1. Шаги сборки — строго по §10 SPEC, один шаг = один PR, зелёный CI обеих ОС.
2. Шаг 2 (model-fetch spike) — до написания рантайма: скачать модели по
   `docs/quant-policy.md`, пересчитать sha256, прогнать parity-гейт (fp32 vs квант,
   golden-набор), померить RSS и латентность, записать в `docs/model-audit.md` +
   `models/manifest.md` (URL+revision+sha256, веса в git не тащим).
3. Кросс-платформенность проверять CI-матрицей (ubuntu-22.04/24.04 + windows-2022),
   не локально. Тяжёлые локальные прогоны (cargo build/test, ONNX-инференс) — в
   щадящем режиме CPU (рулинг оператора 21.10: ноут не нагружать):
   `CARGO_BUILD_JOBS=2`, `cargo test -- --test-threads=2`, `OMP_NUM_THREADS=2`
   для инференса, `nice -n 10` на долгих сборках, один прогон за раз. Это про
   локальные прогоны на машине оператора, НЕ про CI (там свои ядра). Числа
   воспроизводимости (потоки инференса) писать в метод замера.
4. `unwrap()` в prod-коде запрещён линтом (`-D clippy::unwrap_used`).
5. Квант без потери точности (политика оператора 18.10): только по
   `docs/quant-policy.md`; паритет-таблицы чужих экспортов — `[claim]` до нашего
   прогона; fp8 на ORT CPU-EP не исполняется — рабочий путь CPU = int8 weight-only
   + fp16.
6. **Python — gutter-тулинг, не часть продукта** (рулинг оператора 19.10,
   ослабляет версию от 18.10): рантайм и зависимости сборки Rust — Python не
   проникает туда (ни импортами, ни pyo3-биндингами). Разрешён для быстрых
   генераторов шаблонов/данных, разовой разметки и утилит (`data/golden/`,
   `scripts/*.py`). Вся Python-обвязка под uv: `pyproject.toml` + `uv.lock`
   + `.python-version` в гите, запуск только `uv run` (никаких pip вручную);
   линт — ruff, `just python-lint` / `just golden-verify` (побайтовая
   воспроизводимость датасета — гейт против дрейфа правок), CI-джоба
   `python-golden` зелёная на ubuntu+windows. Код ревьюится как постоянный:
   замеченные дефекты фиксируются в README-владельце, не живут молча.
   Конвертация весов/квант — Rust (`safetensors` + свой ONNX-эмитент + ort),
   см. quant-policy п.7 — это не ослаблено. `tools/verify/` (сверочный
   PyTorch-прогон parity) остаётся изолированным вне дерева сборки.

## Что НЕ делаем (решения, зафиксированы)

- Не берём JevK5/генеративную LLM как арбитра (см. SPEC §5.1).
- Не тащим TruffleHog-live-верификацию токенов (сеть нарушает air-gap).
- Не используем готовые обёртки gline-rs/gliclass-rs как зависимость (конфликт ort;
  только как референс кода декодирования).
- Не делаем «диффузионную» разметку — энкодер уже красит весь текст за 1 проход.
