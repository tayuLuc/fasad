# RELEASES

Политика версий и журнал релизов. Процедуры сборки/публикации —
[docs/release.md](docs/release.md).

## Политика версий (SemVer в 0.x)

1. **Единый источник версии** — `[workspace.package] version` в `Cargo.toml`.
   Все крейты наследуют её через `version.workspace = true`; дублировать
   версию в `crates/*/Cargo.toml` запрещено (расхождение = сломанный
   `just _version` и ложная метка артефакта).
2. **0.x = нестабильный API по SemVer** (п.5 SemVer 2.0.0: «0.y.z … включает
   в себя возможность изменений, не совместимых с предыдущими версиями»).
   Следствие для нас:
   - `0.0.x` — растущий каркас, совместимость не обещаем;
   - `0.1.0` — первый релиз с рабочим HTTP-контуром каскада-0;
   - `0.x.y` (`x` растёт) — несовместимые изменения публичного контракта
     (`/v1/*`, `X-Guard-*`, формат `schema.default.json`, env-имена `FASAD_*`);
   - `0.x.y` (`y` растёт) — backfill, багфиксы, новые детекторы/классы,
     новые опциональные env, новые поля в ответах.
3. **Мажор 1.0.0** не раньше, чем: модельный путь (каскады 1–2) сведён в
   демон, `data/golden` раздут до N≥150 и recall-гейт SPEC §5 п.7 зелёный,
   RAM-бюджет SPEC §1 подтверждён на трёх платформах матрицы.
   1.0.0 фиксирует контракт `/v1/*` как обещание.
4. **Формат тега** — `v<semver>` (`v0.1.0`). Триггер релиза — push тега
   (`workflow_dispatch` собирает артефакты, но релиз не публикует).
5. **Имя артефакта несёт факт о сборке**, а не обещание: `fasad-<version>-<triple>-cascade-0.<tar.gz|zip>`.
   Метка контура (`cascade-0`) меняется только вместе с содержимым бинаря
   (`scripts/make-bundle.sh --label`), и её сверяет `scripts/verify-bundle.sh`
   с полем `stage` из `/health`.
6. **Что не версионируется тегами:** модели (их идентичность = `revision` +
   `sha256` в `models/manifest.md`), `docs/SPEC.md` (вторичный источник),
   `schema.default.json` (версия схемы внутри файла).
7. **Запись в этом файле** появляется в том же коммите, что поднимает версию:
   дата, версия, что вошло, известные границы контура.

## 0.1.0 — не выпущен (подготовлен к выпуску)

- Контур релизного бинаря: каскад-0 (детерминированные детекторы + vault).
  Модельного пути спанов в демоне нет — см. docs/release.md §«Что в бандле».
- Платформы матрицы: `x86_64-unknown-linux-gnu` (ubuntu-24.04),
  `x86_64-pc-windows-msvc` (windows-2022), `aarch64-apple-darwin` (macos-14).
- RAM: каскад-0 пик 3.4 MiB (промер 21.10, метод в docs/model-audit.md §9);
  бюджет SPEC §1 1843.2 MiB подтверждён с запасом; Windows не промерен.
- Известные границы: union-recall N≥150 (гейт §5 п.7) не закрыт; витрина
  продукта (README) не написана; подпись артефактов не делается.
