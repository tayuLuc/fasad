# fasad

Локальный AI-гард: один стендэлон-демон на Rust, оффлайн. Размечает текст по
классам ПДн, маскирует обратимо и проксирует OpenAI-совместимые запросы так,
что наружу уходит замазанное, а обратно возвращается развёрнутое. Весь разбор
завершается на 127.0.0.1 до первой сокет-операции (SPEC §1 п.6); телеметрии
нет, сетевой вызов ровно один — явно названный клиентом `X-Upstream-URL`.

Все примеры ниже прогнаны живьём 22.10 на релизном бинаре
`ORT_PREFER_DYNAMIC_LINK=1 ORT_LIB_PATH=<dylib 1.31.0>/lib cargo build --release
--features guard-daemon/ort-inference` (macOS arm64, rustc 1.99.1,
`FASAD_THREADS=2`, веса смонтированы `FASAD_MODEL_DIR` — витрина §2 идёт на
стадии `cascade-0+models`; команда монтажа — §«Как включить монтаж каскадов
1–2» в [crates/guard-daemon/README.md](crates/guard-daemon/README.md));
ответы приведены дословно, без правок. Исключение — значения, которые даёт только что запущенный
процесс (`<маркер N>` в §2, `<nonce>` в §4): они обозваны плейсхолдерами, и
единственный источник значения — вывод предыдущего шага того же прогона.

## 1. Быстрый старт

Нужен Rust 1.99.1 (пин `rust-toolchain.toml`, rustup поднимет сам) и
[just](https://github.com/casey/just) для контракта команд.

```sh
cargo build --release -p guard-daemon --features guard-daemon/ort-inference
export FASAD_MODEL_DIR="$HOME/.cache/fasad-models"   # scripts/fetch-models.sh
./target/release/fasad
```

Баннер смонтированного прогона (продуктовый контур #181/#185: full-бинарь +
веса, порт по умолчанию 8765; промер 22.10, на этом процессе устроена вся
витрина §2; команда и раскладка монтажа — §«Как включить монтаж каскадов
1–2» в [crates/guard-daemon/README.md](crates/guard-daemon/README.md),
`FASAD_THREADS=2`):

```
fasad 0.1.0 cascade-0+models, listening on http://127.0.0.1:8765/health (классов схемы: 8, vault: stateless/strict, ключ: ephemeral)
fasad: UI браузера — http://127.0.0.1:8765/
```

```
fasad: старт невозможен: FASAD_MODEL_DIR не задан: полный контур требует весов (models/README.md в бандле); каскад-0-only — не продакшн-режим
```

### Файл конфигурации и страница «Настройки» (#219, #220)

Приоритет значения: **env > файл > дефолт**. env — то, чем управляют при
запуске (systemd-юнит, `env FASAD_PORT=… fasad`), файл — пользовательский
артефакт; файл env не переопределяет никогда.

Путь файла (`config.rs::config_file_path`): `FASAD_CONFIG` (явный, выигрывает
всё) → Windows: `%APPDATA%\fasad\config` → unix/mac:
`$XDG_CONFIG_HOME/fasad/config`, дефолт `$HOME/.config/fasad/config`
(macOS = та же XDG-форма, НЕ `~/Library/Preferences`). Явный путь в никуда =
отказ старта (опечатка обязана быть названа, #185-контур); отсутствие файла
по дефолтному пути = дефолты.

Формат = собственный KV-парсер, НЕ toml (зависимости `toml`/`toml_edit`/`dirs`
в дереве нет — промер docs/dep-verify-crates.md §17, минимализм AGENTS):

```
# комментарий
FASAD_MODEL_DIR=/Users/me/.cache/fasad-models
FASAD_THREADS=2
```

`KEY=значение` (ровно одна `=`, пробелы по краям снимаются, CRLF читается,
запись пишет канонический LF), регистр ключа не важен. Пустое значение =
«снять override» (дефолт). Пустой `FASAD_CONFIG` = unset (тот же контракт,
что у env: пустое = «оператор ничего не сказал»). Файла нет по
каноническому пути = дефолты (свежая установка стартует); файла нет по
явному `FASAD_CONFIG` = отказ старта (опечатка в пути названа). Строка без
`=` = отказ старта с номером строки. Неизвестный ключ = предупреждение в
stderr (файл переживает релиз с новыми ключами). Значения проходят ТЕ ЖЕ
валидаторы, что env (единая точка, `config::validate_value`); для записи из
UI тихие фолбэки env-запуска отключены: `FASAD_PORT` = разбор `port_strict` (одна
функция на env-файловый и POST-контуры): `0` легален в env/файле («дай
свободный порт» — контракт харнесей и скриптов), контур записи (UI) принимает
только 1024..=65535 (привилегированные = root, «случайный» порт человеку не
нужен),
`FASAD_HF_HOST` бьётся парсером fetch-контура (https обязателен, петлевой
http = env-аффорданс).

Разрешённые ключи файла (реестр `config::FILE_ALLOWED_KEYS`; все применяются
на старте = **требуется перезапуск**):

| Ключ | Дефолт | Прямой env-аналог |
| --- | --- | --- |
| `FASAD_MODEL_DIR` | `$HOME/.cache/fasad-models` | да |
| `FASAD_PORT` | 8765 | да |
| `FASAD_THREADS` | 8 | да |
| `FASAD_TIMEOUT_MS` / `FASAD_READ_TIMEOUT_MS` | 3000 / 30000 | да |
| `FASAD_MOUNT_POLL_MS` | 4000 (0 = выключен) | да; интервал горячего монтажа (#316) |
| `FASAD_MAX_BODY_BYTES` | 1048576 | да |
| `FASAD_VAULT_MODE` | stateless | да |
| `FASAD_GRAY_LO` / `FASAD_GRAY_HI` / `FASAD_TAU_LOW` / `FASAD_TAU_HIGH` / `FASAD_ARBITER_ALPHA` | 0.22 / 0.80 / 0.20 / 0.80 / 0.5 | да (инвариант `low ≤ lo < hi ≤ high` проверяется общим отказом) |
| `FASAD_UPSTREAM_ALLOWLIST` / `FASAD_PROXY_LOOPBACK_HTTP` | пусто / выключен | да |
| `FASAD_FRAME_MIN` | 0.95 (диапазон (0.5, 1]) | да; вес каркасного хита «каркас+форма без чексуммы» (#234). | `FASAD_TRANSLIT` | 1 (включена) | да; контур #238: кандидат серой зоны + арбитраж; активен при инварианте `α·gray_lo < τ_low` (связка дефолтов 0.5·0.22<0.20), настройка порогов = ответственность оператора, при невыполнении контур выключается с причиной в stderr |
| `FASAD_HF_HOST` | `https://huggingface.co` | да |
| `FASAD_SCHEMA` | встроенный канон | да (только файл/env, не UI) |

Запрещены в файле (отказ старта с причиной): `FASAD_VAULT_KEY` (секрет не
живёт открытым текстом на диске — AGENTS; только env), `FASAD_BIND`
(loopback-инвариант = env/юнит), `FASAD_MLOCK` (решение развёртывания),
`FASAD_TEST_CASCADE0` / `FASAD_TEST_TRAY_CONTOUR` (харнес-флаги: файл не имеет
права делать из релизного бинаря каскад-0), `FASAD_CONFIG` (сам себя файл не
задаёт).

UI (#220): страница «Настройки» (второй таб песочницы) = карточка весов +
форма этих ключей: `GET /v1/config` (эффективные значения + источник
env/file/default; секреты не отдаются никогда — `FASAD_VAULT_KEY` = строка
«задан/нет»), `POST /v1/config` (белый список, те же валидаторы, запись
атомарно `.part`+rename; успех = «требуется перезапуск»). Hot-reload нет по
решению #219: монтаж весов и сокет = старт-время.

Адрес и порт в настройках (#227, решение оператора: LAN-режим = НЕТ).
**Порт** — настраиваем поле `FASAD_PORT` той же формы (#224: number
1024..65535, `POST /v1/config`, «требуется перезапуск»). **Адрес** —
read-only строка «адрес интерфейса» = `window.location.origin`, то есть
эффективный url, по которому браузер реально открыл песочницу (`localhost`
и `127.0.0.1` = одно и то же, строка не врёт ни при каком бинде), с кнопкой
копирования. **Бинд** (`FASAD_BIND`) из UI не редактируется навсегда:
loopback-инвариант SPEC §1 п.6 = решение развёртывания, только env при
запуске (#224; `0.0.0.0` = отказ старта, гард без TLS/аутентификации не
выезжает в LAN).


### Полный цикл за 60 секунд в UI (#202, ручная проверка «смысл цел, ПДн нет»)

Демон запущен, браузер открыт по строке `UI — http://127.0.0.1:8765/` из
баннера. Шаги (кнопки подписаны номерами 1-2-3 над ними, UI = владелец
подсказок; для «чата» демона запускают с `FASAD_UPSTREAM_ALLOWLIST=<хост>`
и адресом upstream в поле панели):

1. «Пример» — в поле текст демо-документа (деловое письмо ~2.8 КБ,
   все 8 классов схемы + формы #200 + платёжная связка #225 + невалидные
   номера с каркасом #234 (СНИЛС …95 / ИНН 5027196012 / ОГРН …1110 =
   0.95 «frame_invalid»: маскируются, в таблице читается валидатор) с проверяемым
   итогом: сумма 1 224 000 ₽, аванс 30 % = 367 200 ₽, остаток 856 800 ₽ —
   после расшифровки ответа числа должны вернуться глазами; при первом
   открытии подставляется сам, галочка «больше не показывать» = localStorage).
2. «Разобрать» — раскраска по уверенности + таблица спанов. Порог `S`
   (поле «Порог S», семантика — hint над полем, #245/#249): применённый
   порог = `max(S, FASAD_TAU_LOW)`, дефолт поля 0 = серверная планка 0.20;
   дефолт ПОЛЯ = 0, не 0.99; «маскировать только ≥99 % уверенных» = тихий
   выключатель 0.95-контура (#234) и серой зоны модели (#246 п.в — дефолт
   НЕ менялся, дискуссия в PR #246). Над таблицей легенда (#246): «в списке
   маскируемые; полный разбор = панель РАЗБОР»; счётчик «снято порогом: N»
   = разница базового прогона (без порога) и показанного.
3. «Обезличить» — окно «Что ушло (обезличено)»: ПДн = токены; кнопки
   «Скопировать обезличенный» = тот текст в буфер и «Скопировать с задачей»
   (#225) = тот же текст + фиксированная задача-обёртка + список найденных
   меток из ответа `/v1/anonymize` (вставить в свой чат целиком: модель
   заполняет таблицу реквизитов Literally по меткам, проверяет арифметику
   письма и перечисляет паспортно-карточные числа — ответы проверяемы).
4a. БЫСТРЫЙ ПУТЬ (прокси, короткие куски): «В чат через прокси» — обезличенный
   уходит в ваш LLM-чат через гард (X-Upstream-URL, allowlist #68, SSE по мере
   генерации) — окно «Ответ ИИ (с токенами)». Бюджет = абзац (~350 Б):
   окно экстрактора прокси меряет в subword-токенах (#84, промер ревью #203:
   ≲3 подмены stateless / ≲12 меток session; полный документ = 502
   `cascade_unavailable` честно).
4b. ПОЛНЫЙ ПУТЬ (без прокси, весь документ): «Скопировать с задачей» (#225;
   или «Скопировать обезличенный») →
   вставить в свой чат (в любой, гард тут не нужен) → ответ вставить в поле
   «…или вставь ответ из своего чата» → «Раскрыть вставленный».
5. «Раскрыть ответ» (или «Раскрыть вставленный») — текст проходит
   `/v1/deanonymize` = оригиналы в окне «Ответ с оригиналами» (строка
   «токенов в ответе: N | токенов раскрыто: M» — счётчик считает обе формы
   меток, `[[F0#…]]` и `[КЛАСС_н_…]`) — вот и вся ручная проверка: гард
   прозрачен для смысла и обратим для вас. Чек-лист #225 под окном:
   «раскрыто N из M» (M = метки последней подмены; не вернувшиеся — красный
   список) и «остаточные метки» (форма метки в ответе ПОСЛЕ deanonymize =
   модель мутировала метку, замена не распознана).
6. «Новая сессия» — очистка vault-записей этой вкладки; «Развернуть» =
   побайтовый исходник в окне «Исходник вернулся» («побайтово совпал: ДА»).

## 2. Три запроса, ради которых продукт ставят

### analyze

```sh
curl -s -X POST localhost:8765/v1/analyze \
  -H 'content-type: application/json' \
  -d '{"text":"Ушакова Кира Саввична, ИНН 2482014338, СНИЛС 65707715421"}'
```

Ответ — голый массив спанов (контракт Presidio `AnalyzerResult`; `start`/`end`
в символах, `byte_start`/`byte_end` в байтах). Блок ниже — дословный вывод
демона (промер 22.10, релизный бинарь `596f249` с фичей `ort-inference`,
стадия `cascade-0+models`, `FASAD_THREADS=2`); порядок элементов — живой
порядок ответа демона (`inn, snils, person_name ×3`), не сортировка по

потолка 1024 Б (#120, до него запрос ниже блокировался `503 span_too_long`
навсегда; строка границы — §7 п.4). Вход — фикстура слоя 223 Б
(`crates/guard-daemon/tests/vault_span_cap.rs`, ИНН-12 словами —
золотое значение `825082492964`, фраза дословно из константы `INN12_WORDS`):

```sh
curl -s -X POST localhost:8765/v1/analyze -H 'content-type: application/json' \
  -d '{"text":"ИНН контрагента: восемьсот двадцать пять миллиардов восемьдесят два миллиона четыреста девяносто две тысячи девятьсот шестьдесят четыре, просим проверить"}'
```

`/v1/analyze` (промер 22.10 на смонтированном процессе, латентность 338 мс,
повторы 388 / 321 / 375) отдаёт один спан `{"entity_type":"inn","start":17,"end":135,
"score":1.0,"byte_start":31,"byte_end":254,"source":"checksum_rf",
"validator":"inn12"}` — спан на фразу словами; `/v1/anonymize` с этими
координатами заменяет фразу маркером (тело маркера — 68–80 символов на спан:
тело случайно по nonce, промер 22.10 по пяти спанам витрины — 79/71/68/74/75;
на 223-байтовом спане тело 283, токен 283; граница worst-case
`MAX_MARKER_BYTES` = 1594 на токен 1587, `crates/guard-vault/src/token.rs:121`
и asserts `token.rs:1423-1424`, следствие поднятого потолка — stateless-токен
спана под 1024, §7 п.4),
`/v1/deanonymize` того же процесса возвращает оригинал (`substituted: 1`, `restore_refused: 0`, `cmp` rc=0 на 287 Б).

Почему маркеры — плейсхолдеры, а не литералы: без `FASAD_VAULT_KEY` ключ
AES-256-GCM генерируется из CSPRNG на старт процесса (`vault.rs:474-478`, в баннере
`ключ: ephemeral`) и живёт до рестарта — разворачивает только тот процесс, который
маркер выдал. Литералы этого блока до правки #115 — маркеры процесса, которого больше
нет, их копипаст отвечает
`422 {"error":{"code":"unresolved_token","message":"не развернулось маркеров: 2 — отдаём отказ, а не partial-restore"}}`
(промер 21.10 на релизном бинаре, два независимых процесса; переснято 22.10
живым curl'ом — текст тот же, счётчик равнен числу маркеров в копипасте:
копипаст пяти маркеров чужого процесса отвечает `…маркеров: 5…`, промер 22.10);
маркеры своего прогона разворачиваются в исходный текст байт-в-байт,
`substituted: 5`. Угловые скобки `<маркер N>` не входят в алфавит тела
маркера — `A-Za-z0-9-_` (`rewriter.rs:41`), —
и демон их не разворачивает и нерезолвнутым не считает: `substituted: 0`, текст
проходит нетронутым (переснято 22.10 тем же curl'ом). Обратимость, переживающая
перезапуск, — `FASAD_VAULT_KEY` (§1, §4).

### proxy

Прокси — единственная дверь наружу, и она открывается только по явному адресу
клиента (proxy.rs, §«Две стенки»). Наружу уходит замазанный запрос, обратно —
развёрнутый ответ; из клиентских заголовков переносятся только `authorization`
и `x-api-key` (proxy.rs:603), ключ демона не хранит. Значение заголовка в примере
— плейсхолдер `sk-REPLACE-ME`, подставьте свой: угловые скобки в значении
заголовка недопустимы, с ними маршрут отвечает `502 upstream_protocol` (промер
21.10 на значении `<ваш ключ…>`).

```sh
FASAD_UPSTREAM_ALLOWLIST='api.openai.com' ./target/release/fasad
```

```sh
curl -s -X POST localhost:8765/v1/chat/completions \
  -H 'content-type: application/json' \
  -H 'Authorization: Bearer sk-REPLACE-ME' \
  -H 'X-Upstream-URL: https://api.openai.com/v1/chat/completions' \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"ИНН 2482014338 — позвони Ушаковой Кире Саввичне"}]}'
```

Полный цикл проверен живьём на loopback-upstream (эхо-сервер на
`127.0.0.1:8199`, запуск с `FASAD_PROXY_LOOPBACK_HTTP=1` и
`FASAD_UPSTREAM_ALLOWLIST='127.0.0.1:8199'`): в тексте запроса ИНН ушёл наружу
замаркированным (`x-guard-redacted-count: 1`), в ответе разворачивается обратно,
`finish_reason: stop`. Промер 21.10 тем же curl'ом, что выше, но с
`X-Upstream-URL: http://127.0.0.1:8199/v1/chat/completions` — на адрес вне
allowlist (`https://api.openai.com/…`) этот rig отвечает `403`
`allowlist_denied`, а `FASAD_PROXY_LOOPBACK_HTTP=1` ничего не переадресует: он
разрешает http только на loopback (proxy.rs:373) и снимает `https_only` с
агента (proxy.rs:473). На loopback-URL: тело, ушедшее upstream, содержит
маркер `[[F0#…]]` и не содержит ИНН; ответ разворачивается в
исходный текст байт-в-байт (`cmp` rc=0); заголовок `authorization` долетел
дословно. Без allowlist маршрут отдаёт `403` (промер):

```json
{"error":{"code":"allowlist_empty","message":"FASAD_UPSTREAM_ALLOWLIST пуст, прокси выключен"}}
```

`X-Guard-Policy: block` на этом маршруте уважается (запрос не уходит),
`audit_only` отвергается с `400 policy_not_applicable`: клиентским заголовком
нельзя снять с гарда его единственную работу.

## 4. Режимы хранилища

`FASAD_VAULT_MODE` принимает четыре значения (config.rs: «допустимо
2|3|session|stateless»), семантик у них две (SPEC §3.2 и §3.3):

| Значение env | Режим | Маркер | `X-Session-ID` | Обратимость |
| --- | --- | --- | --- | --- |
| `stateless` (дефолт) | SPEC §3.3 | `[[F0#base64url]]`, AES-256-GCM, AAD = id сессии | не нужен | тем же процессом |
| `3` | он же, числом | он же | не нужен | тем же процессом |
| `session` | SPEC §3.2 | метка `[КЛАСС_seq_nonce]` + суррогат ФИО, оригиналы в кэше (idle 15 мин, live 2 ч) | обязателен | тем же процессом; с `FASAD_VAULT_KEY` — переживает перезапуск |
| `2` | он же, числом | он же | обязателен | она же |

Stateless-контур (режим по умолчанию) на том же тексте и двух числовых спанах
`49..59`/`72..83` (промер 22.10, смонтированный процесс): ответ —
`Ушакова Кира Саввична, ИНН [[F0#<маркер 1>]], СНИЛС [[F0#<маркер 2>]]`
(ФИО не замазано: в запросе маскируются только присланные спаны),
`/v1/deanonymize` того же процесса — `substituted: 2` и оригинал побайтово
(`cmp` rc=0). Витрина §2 маскирует все пять спанов этого же текста.

Промеры живым запросом (режим 2, тот же текст, промер 21.10):

1. Без заголовка: `400 {"error":{"code":"bad_request","message":"режим 2 требует заголовок X-Session-ID"}}`.
2. С `X-Session-ID: demo`: `ИНН [INN_1_<nonce>], СНИЛС [SNILS_2_<nonce>]` —
   `<nonce>` один на все метки этого прогона, значение даёт этот шаг.
3. `/v1/deanonymize` в сессии `demo` возвращает оригиналы (`substituted: 2`): на
   входе текст из вывода п.2, с теми же `<nonce>`.
4. `/v1/deanonymize` с чужим `X-Session-ID`: `422 {"error":{"code":"unresolved_token","message":"не развернулось маркеров: 2 — отдаём отказ, а не partial-restore"}}`.
5. Баннер печатает `ключ: env` или `ключ: ephemeral` — во втором случае
   обратимость умирает вместе с процессом.

`<nonce>` не берут из документации: он генерируется при регистрации сессии
(`vault.rs:803-816`, случайные байты) и в каждом прогоне новый. Единственный
источник значения — ответ `anonymize` (п.2), и п.3 разворачивает ровно те метки,
которые вернул п.2 того же прогона.

## 6. Границы

1. Один пользователь, одна машина: bind вне loopback запрещён самим демоном.
2. Остаточный риск реверс-индекса назван в
   [docs/daemon-scope.md](docs/daemon-scope.md) (строка 33) — вероятность на одно
   событие перенятого слота; формулу сюда не переносим: цитата её и есть
   перепечатывание.
3. Лимиты реестра: 256 сессий (FIFO, `MAX_SESSIONS`, vault.rs:114) и 1024 ФОРМ
   СУРРОГАТОВ на сессию (`MAX_FORMS_PER_SESSION`, config.rs:46). Считаются формы
   подмен, а не метки: одна ФИО-подмена даёт до 4 форм, то есть 1024 — это ~256
   ФИО (config.rs:35-45). Переполнение — `422 too_many_forms` до первой подмены, а
   не тихая потеря формы (потерянная форма дала бы partial-restore, то есть
   fail-open на данных); закреплено тестом
   `forms_cap_refuses_request_before_first_substitution` (`vault.rs:1530`). С
   каскада-0 (стадия харнесов/тестов; full-бинарь без весов не стартует, #185)
   порога не достичь: форму
   плодит подмена ФИО, а её детектор — каскад 1; на смонтированной сборке
   (ФИО-спаны витрины §2) счёт форм становится достижимым.
4. Отсутствие `X-Guard-Redacted-Count` на 2xx-ответе маршрутов разбора и прокси
   (`/v1/analyze`, `/v1/anonymize`, `/v1/deanonymize`, `/v1/sessions/{id}`,
   `/v1/chat/completions` — http.rs:218-227, proxy.rs:561) клиент обязан считать
   ошибкой: демон никогда не подменяет счётчик нулём, если не знает значения. У
   `/health`, `/ui` и `/assets/*` этого заголовка нет по устройству — 200 без них
   является нормой.
5. `panic = "unwind"`: паника одного запроса не валит демон, но и не обещает
   «неубиваемости» — это контур изоляции отказа, а не отказоустойчивость.
6. Скриншотов нет: витрина — команды и живые ответы этой страницы.

## 7. Лимиты

Список того, что продукт честно НЕ закрывает, с ценой и первичкой. Формат —
по образцу «Что каскад 0 находит и не находит» в
[docs/daemon-scope.md](docs/daemon-scope.md); числа этой секции — не перепечатка:
каждая строка называет промер или тест, который её держит.

1. **Бюджет смонтированного конвейера = функция длины входа.**
   `FASAD_TIMEOUT_MS=3000` (дефолт) на стадии `cascade-0+models` живёт ровно до
   первого серого спана: Decide-чанк промерен в 4.5–8.6 с (`threads=2`,
   [docs/model-audit-inference.md](docs/model-audit-inference.md) §I1),
   lockR-чанк — 329–445 мс (та же таблица §I1). Бюджет считают не по чужому
   масштабу, а по формуле §I1 п.4: `FASAD_TIMEOUT_MS ≳ N_lockR·300 +
   N_decide·8000` мс при `FASAD_THREADS=2`, где `N_*` — число чанков (окно
   lockR 256 токенов + overlap 32; геометрия Decide — `ChunkCfg::default()` =
   384/32, §I1, метод счёта чанков — вызов продуктового
   `guard_onnx::chunker::chunk`). Дефолт покрывает витрину §2 (279–416 мс,
   промеры 22.10 четырёх свободных процессов, §2), 44 Б и 230 Б; 8 КБ — НЕ покрывает (2 958 мс
   на свободной машине против 3 636 мс под фоновой нагрузкой, §I1 п.4):
   длинные документы на проде требуют тюна. Край окна — честный `502`: чанк,
   не влезший в окно (латинская/цифровая плотность).
2. **Круглые количества словами дают ИНН-ложняк (задокументированная цена
   #118).** «Пять миллиардов» = 5000000000 проходит валидатор ИНН-10 и
   маскируется как ПДн — тест `spelled_round_billion_is_the_documented_tradeoff`
   (`crates/guard-daemon/src/cascade0.rs:1983`, первичка
   [docs/daemon-scope.md](docs/daemon-scope.md) §«Что каскад 0 находит и не
   находит» п.4). Это осознанный обмен FN→FP: FN (утёкший номер) фатален, FP
   дёшев благодаря обратимости маскирования (инвариант AGENTS). Guard года
   («числа короче 9 цифр валидаторам не передаются») от этой ловушки не спасает
   — в «пяти миллиардах» 10 цифр.
3. **Транслит RU↔LAT не нормализуется (issue #51 п.1, состояние OPEN — промер
   `gh issue view 51` 22.10).** Латинская транслитерация ФИО (`Ушаков` →
   `Ushakov`) для детерминированного слоя невидима — предмет и гейт приёмки
   названы в первичке issue #51 п.1.
   Обходы закрыты в слоях base64 (#94) и числительных (#118/#120). С #238
   транслит закрывает ЭВРИСТИКА СЕРОЙ ЗОНЫ (контур A′): окна заглавных
   слов латиницы (`Ushakov Petr Sergeevich`, `Sokolov D. A.`) подаются
   модельным кандидатом с `p1 = gray_lo`, вердикт выносит арбитр каскада
   2 (бренды/гео с низким p2 отсекаются арифметикой `S = α·p1+(1−α)·p2`).
   Контур живёт ТОЛЬКО при смонтированных весах (на стадии cascade-0-only
   серой зоны нет = транслит остаётся FN, это и мерит демо-коммент
   витрины); активен при инварианте `α·gray_lo < τ_low` (дефолты SPEC ✓),
   `FASAD_TRANSLIT=off` = выключен. Первичка issue #51/#238,
   `crates/guard-detectors/src/translit.rs`. Golden-подтверждение =
   v1.7 (после влития #215, нумерация по первичке main).
4. **Потолок спана маскирования = 1024 Б (`MAX_ORIGINAL_BYTES`,
   `crates/guard-vault/src/token.rs:72`).** Спан длиннее — `/v1/anonymize`
   отвечает `503` с причиной в теле (промер 22.10 живым curl'ом на фикстуре
   1025 Б, дословно):

   ```json
   {"error":{"code":"span_too_long","message":"vault:span_too_long len=1025 max=1024"}}
   ```

   Контракт пинит `crates/guard-daemon/tests/vault_span_cap.rs`. До #120 потолок
   был 128 Б и навечно блокировал прокси ровно на словесных реестровых номерах
   (ИНН-12 словами = 223 Б); после #120 словесный ИНН маскируется и
   разворачивается байт-в-байт (витрина §2). ENV-ручки нет намеренно: потолок
   входит в размер слота залоченного пула
   (`POOL_SLOTS·POOL_SLOT_BYTES` = 16×2176 Б = 34 КиБ, const-assert «пул
   влезает в 64 KiB»). Цена поднятия: stateless-токен худшего спана 1587
   символов (первичка #120, docs/daemon-scope.md п.4); на витринном словесном
   ИНН-12 тело маркера — 283 символа, токен 283 (промер 22.10, §2; на спанах
   витрины тело 68–80 символов — случайно по nonce).
5. **ФИО отдаётся усечёнными спанами.** Границы рисует каскад 1: на витрине §2
   патроним `Саввична` (символы 13–21) усечён спаном `Сав` (13–16) — модель
   красит начало патронима, хвост обрывается; координат у каскада 2 нет (#41),
   понизить границу он не может (промер 22.10, cmp-эталон §2). Маскирование от
   этого не страдает: усечённый спан маскируется и разворачивается
   байт-в-байт (round-trip §2). Практический смысл строки: остаток `вична`
   остаётся в открытом виде — клиенту, которому важно имя целиком, отдавать
   спан самому (выделение в интерфейсе, `/v1/anonymize` принимает спаны
   клиента).

### Язык текста (`scripts/scan_lang.py`)

Гейт ловит утечки график в технические артефакты, а не язык prose: CJK,
арабицу (U+0600-U+06FF), иврит (U+0590-U+05FF), деванагари (U+0900-U+097F) и
склейку кириллицы с латиницей внутри одного слова (`fp16-квант` чисто, слитное
написание — нет). Чистая кириллица не красится нигде: русские UI-тексты и
документы легальны по построению (#121 — про арабицу/иврит/деванагари, не про
кириллицу).

- Под `--all` — 148 файлов (промер: git-инвентарь ∩ текстовый фильтр, было 143).
  Суффиксы: `.md .rs .py .toml .yml .yaml .json .jsonl .tsv .sh .txt` и #119 —
  `.js .css .html .hbs .c` (слепая зона whole-tree: `crates/guard-daemon/ui/app.js`,
  `ui/app.css`, `ui/index.html`, `about.hbs`, `crates/guard-onnx/spike/rss_mach.c`,
  промер `git ls-files | grep -E '[.](js|css|html|hbs|c)$' | wc -l` = 5) плюс имена
  без расширения (`justfile`, `LICENSE`, dotfiles — #103).
- Исключение — построчная директива `scan-lang:` + `allow` (в тексте о директиве
  токен пишут разрывом, иначе она красит прогон как мёртвая): 19 директив в 8
  файлах, 74 разрешённых хита — тесты с полноширинными цифрами и доки про
  чексуммы. Мёртвая директива (строка без хита) красит прогон; файловых
  исключений нет — это способ потерять гейт. Пяти файлам из #119 allow не нужен:
  живая кириллица (app.js 1554, about.hbs 581, rss_mach.c 569, index.html 428,
  app.css 118 символов) хитом не является.
- Запуск — из корня репозитория: вне корня `rc 2` + `reason|cwd-not-repo-root`
  (#116 N2; до правки обход печатал 143 строки skip и `reason|no-readable-file` —
  правда о результате, ложь о причине). Из-под `just` эта ветка недостижима: `just`
  ставит `cwd` = каталог justfile, т.е. всегда корень (#125 N5 — защита прямого
  вызова `python scripts/scan_lang.py`).
- `--self-test` — positive control, обязателен: посад CJK/арабицы/иврита/
  деванагари — по три ноги на каждую графику (нижняя граница блока, середина,
  верхняя: mid-only переживал сдвиг Arabic lo 0x0600→0x0620 зелёным, #125 N2),
  чистая кириллица обязана остаться чистой, пара инвентаря «app.js
  входит / model.wasm не входит», живость фильтра обхода и предиката корня.
  Мёртвый контроль = `rc 2` (промер мутациями: выключенный диапазон, вычеркнутый
  суффикс, сдвинутая граница блока и `return True` в предикате каждый гасят контроль).
- Коды возврата: `0` чисто, `1` найдены хиты, `2` проверка не выполнена — в т.ч.
  недоступный рабочий каталог (`reason|cwd-unavailable`, #125 N1: `Path.cwd()`
  стоял вне `try`, getcwd удалённого каталога = `FileNotFoundError` → traceback →
  `rc 1` = «найдены хиты»). Достижимо и локально: промер 22.10 на macOS 26.6.2
  (mkdir → chdir → rmdir при открытом fd, запуск через `posix_spawn`) — getcwd
  бросает `FileNotFoundError` и здесь (утверждение issue «macOS отдаёт устаревший
  путь → rc 2» опровергнуто промером): база `dce45f1` = traceback + `rc 1`, head =
  `LANG|cwd|unavailable|FileNotFoundError` + `rc 2 reason|cwd-unavailable`.

Тяжёлые локальные прогоны — в щадящем режиме CPU (AGENTS §3, рюлинг оператора
21.10): `CARGO_BUILD_JOBS=2`, `cargo test -- --test-threads=2`, у харнесов
инференса потоки рычагом `--threads 2`, `nice -n 10`, один прогон за раз;
готовая обёртка того же набора — `just local-test`. `OMP_NUM_THREADS` на нашей
сборке инертен (вендорный `libonnxruntime` osx-arm64 собран без OpenMP), а
`FASAD_THREADS` инертен на каскад-0-контуре харнесов/тестов по причине из
таблицы §1 (full-бинарь без весов не стартует, #185).
