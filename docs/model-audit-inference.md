## I2. α-калибровка смесителя серой зоны и границы τ_low (issue #85, промер 21.10)

Промер-данные: решение об α принимает оператор, дефолт `DEFAULT_ALPHA = 0.5`
(`config.rs:71`) этим прогоном НЕ изменён. Ручка `FASAD_ARBITER_ALPHA` живая
(цена — однострочный пример в п.7).

1. Семантика (первичка кода, не SPEC): `S = α·p1 + (1−α)·p2` — `blend`
   (`cascades.rs:308`); перескориваются только спаны серой зоны
   `0.22 ≤ p1 < 0.80` (`in_grey_zone`, `DEFAULT_GRAY_LO/HI` = `config.rs:59,62`)
   контекстно-зависимых классов (схема: model ∧ пустые validators =
   person_name, address, phone, email, passport — `CascadeCtx::of`), затем
   финальный гейт `S ≥ τ` (`RoutingCfg::single`, `pipeline.rs:379`).
   Issue #85 в теле меняет местами подписи: по коду α=1 = S=p1 =
   «каскад-1 соло», α=0 = S=p2 = «Decide соло» (в тексте issue — наоборот).
2. Метод. Харнес `tools/metrics/union_recall.py` дополнен прогонным режимом
   `--alpha 0,0.25,0.5,0.75,1.0 --gray 0.22,0.80` (metrics tool, прод-код не
   тронут): `blend_lock` = зеркало `apply_arbiter`, счёты per-α на одной
   инференс-выборке; селф-тест `PRECHECK|alpha|…` (числа из прод-тестов
   cascades.rs: 0.65/0.15) гонится до загрузки весов; при α=1.0 строки
   режима совпадают с baseline-строками того же прогона (тождество blend).
   Дата 21.10.2026; машина Darwin-arm64; python 3.13.13, onnxruntime 1.31.0,
   numpy 2.5.4; threads=2 (intra/inter_op, OMP инертен — model-audit.md §5.7), nice -n 10,
   один прогон за раз; каскад 0 — релизный бинарь `target/release/fasad`
   (демон cascade-0-only, FASAD_THREADS=2); веса — sha из артефакта
   (`UNION|sha`): lockR fp16 `039aba6be0c6…`, Decide q4f16 `93f3e0d4ed8b…` +
   `df2b05dc97ff…` (манифест, без перекачки); датасет golden-v1.jsonl
   `546d8c3593d4…` (N=204 строк = 150 recall / 54 negative, 358 recall-спанов);
   `TIME|total` 287.14 с и 273.44 с. Детерминизм: два полных прогона
   (`/tmp/alpha85/grid.raw`, `/tmp/alpha85/grid2.raw`) — все 30 строк
   `ALPHA|a|` совпали diff'ом. Сырые артефакты per-α:
   `/tmp/alpha85/{0.00,0.25,0.50,0.75,1.00}.raw` (раскладка grid2.raw),
   tmp-волатильность: таблицы ниже — дословная выгрузка, не перепечатка.

5. Границы серой зоны и τ_low (сетка τ ∈ {0.20, 0.22, 0.25} при всех α):
   - Планка 98.43 (exact union 357/358, wilson_lo) держится только при
     τ_low = 0.20. При τ_low = 0.22/0.25 — 356/358, wilson_lo 97.99 < 98.0,
     `deficit_spans|1`: планка проседает, 0-дефицита на 357/358 нет.
   - Проседание даёт НЕ каскад-1: столбцы lockR идентичны на всех τ
     (below 0.22 = 0 во всех классах — спанов lockR в полосе [0.20;0.25) на
     golden нет), каскад 0 инертен (скор вето 1.0). Проседает метрический
     dec-arm: харнес применяет thr и к row-credit Decide (p2 ≥ thr),
     person_name 55→54, snils 16→14→11. В проде τ_low gate'ит только
     координатные стадии, поэтому на механизме продукта τ_low = 0.22 инертен
     (нечему отсеиваться); просадка — свойство меры харнеса.
   - Вердикт по границам: τ_low 0.20 не двигаем (SPEC 0.22 — [claim],
     промером не поддержан: у продукта от 0.22 ни выигрыша, ни проигрыша,
     у гейта метрики — дефицит 1 спана и wilson_lo под планкой);
     gray [0.22; 0.80) оставляем: сужать/расширять нечем — на golden зона
     арбитража не даёт измеряемого эффекта ни при каких α.
6. Вывод-кандидат оператору: «α = __ максимизирует закрытые FN при FP-дельта
   ≤ __» на этом датасете не формулируется: ΔFN = ΔFP = 0 при всех

   право числа без данных. Чтобы α стал измерим, нужна калибровочная
   выборка: bait-FN спаны в [0.22; 0.80) с p2 = yes и bait-FP в той же зоне
   с p2 = no (существующий negative-сплит не годится: 17 из 19 FP — выше
   0.80).
7. Ручка (цена примера, дефолт не тронут): `FASAD_ARBITER_ALPHA=0.75
   FASAD_GRAY_LO=0.22 FASAD_GRAY_HI=0.80 fasad` — конфиг валидируется
