## 3. Ключевой вопрос §1.8: маппинг external data

Сессия арбитра (graph + external data 523 МБ) поднялась с RSS 7.5 → **269.0 MiB (первый прогон) / 250.3 MiB (второй прогон, воспроизводимость ±7%)**.
Вывод: q4f16 external data **НЕ маппится целиком в resident-RSS** — ORT лениво/
частично подгружает веса (промер private-RSS `task_vm_info.internal`, «Память»
как в мониторе активности). Бюджет SPEC §1 (≤1.8 ГБ):
355 МБ (lockR fp16, полный load ожидается в шаге 4) + ~0.3 ГБ арбитр-резидент
+ арены/токенизаторы/буферы ≈ **0.9–1.2 ГБ прогноз — вписывается**, окончательный
вердикт после промера lockR-сегмента (см. [model-audit-weights.md §W2](model-audit-weights.md):
инференс-прогон упал на GatherElements до lockR-мерки).

### 10.9 Функциональный обрыв, найденный этим прогоном: «№»

Первый же прогон упал на строке `g0133` («Договор оказания услуг № 782/24 …») с
`502 cascade_unavailable: сбой инференса: decide: констрэкт разметки: 1 токенов
[UNK] в живом входе`. Хронология факта (промер `tokenizer.json` обоих весов в
этом раунде, правит неточность 4b-3C): у каскада 1 `№` ЕСТЬ в словаре (Spiber rubert, WordPiece 120138: `№` = id 248,
сплайс не ломается); у каскада 2 (Unigram 128000) ни один токен не содержит
`№`, а `[UNK]` = id 3 = ровно тот `UNK_ID`, который ветоит `check_splice`
(`arbitrate.rs:48,579`); запись 4b-3C «`№` = [507, UNK]» в
`recall_golden.rs:320` приписана Spiber, а 507 в словаре Decide = `▁` (в rubert
507 = `##́`) — то есть наблюдение сделано на Decide-токенизаторе. Харнес
подменяет `№` пробелом перед прогоном Decide (row-level мере координаты не
нужны, `unk_rows` в счётчике прогона), продукт подменить текст не может —
координаты спанов это байты оригинала. 16 строк из 185 (20 из 204, промер
`data/golden/golden-v1.jsonl`) содержат `№`, а пропуск зафиксирован один:
каскад 2 вызывается только в серой зоне.

Политика после правки (#87): `ArbError::Layout` = деградация каскада 2 (вердиктов
нет, серый спан остаётся на `p1 ≥ 0.22 > τ = 0.20` ⇒ спан не теряется, пропадает
только способность арбитра двигать оценку), остальные ветки `ArbError` = 502.
Отказывать такому входу 502 = не обслуживать весь класс договоров; это не
fail-closed, а отказ от работы. Полный прогон после правки: 185 строк, 1
пропуск Decide (та самая `g0133`), rc=0. Настоящее лечение — #88 (заведено по итогам этого прогона).

### 10.10 Лечение #88: канонизатор входа Decide + цена ограничения (промер 27.10)

Лечение (`crates/guard-onnx/src/arbitrate.rs::canonicalize_decide_input`,
вызов внутри `arbitrate_chunked` до чанковки): `№` (U+2116, 3 Б) → `Nо` = <!-- scan-lang:allow -->
ASCII `N` (U+004E, 1 Б) + кириллическая `о` (U+043E, 2 Б) = ровно 3 Б —
байт-сохраняющая замена (первичка rev 18271032: `Nо` → `▁N`+`о`, оба словарных, <!-- scan-lang:allow -->
0 UNK; decode сохраняет слова g0133 — check_splice-стиль промера; нормалайзер
токенизатора Sequence[Replace→NFC→Strip] на `Nо` = identity = идемпотентно). <!-- scan-lang:allow -->
Варианты отклонены промером: п.1 issue #88 «канонический маппинг» (NFKC
`№`→`No`) = 2 Б, длину ЕХАЕТ (чанкинг режет по байтам канона); `NN` = 2 Б —
тоже ехает; 3-байтный `№` (U+0416) нормалайзером (NFC) не трогается, НО
кириллица U+0416 в слове «услуг№» меняет лексему (не фонетический аналог,
а другая буква); NFKC в целом не идемпотентен: `NFKC(NFKC('№'))='No'≠'№'`. Харнес (`recall_golden.rs`) зовёт тот же канон —
пара харнес↔продукт на номерных входах сходится (прежняя ad-hoc
`№`→пробел меряла харнесу другой вход).

**Инвентарь (пересъёмка golden v1.10, N=287; первичка `tokenizer.json`
Decide, `tokenizers` 0.23.3, byte_fallback=false):** строки с `№` = 21;
UNK-строки = ровно они же (21/21), других UNK-литер в датасете НЕТ
(полный скан). Прежнее число 20/204 (и 16/185) — snapshot v1.6; хвост
v1.7–v1.10 (+83 строки) добавил одну номерную строку.
Окно продукта (≤200 симв.) на N=287 = 268 строк (прежнее 185 — snapshot
окна ≤200 на v1.6; тест `product_coverage_on_the_whole_golden` берёт всё
окно, число переснимется с прогоном), из них 17 с `№`.

**Цена (issue #88 п.2):** золотые спаны, лежащие на 17 канонизируемых строках
окна (union-кредит Decide был под угрозой пропусков): `ogrnip` 5, `snils` 4,
`person_name` 4, `email` 4, `phone` 3, `card_pan` 2, `address` 2, `iban` 1,
`inn` 1 (26 спанов). Реальных пропусков каскада 2 за полный прогон было 1
(`g0133`): Decide зовётся только в серой зоне, «№» в заголовке сам по себе
серую зону не создаёт — строки без серой зоны канонизатором не затрагиваются
поведенчески (вход байтово идентичен, за исключением литеры).

**Остаточное ограничение (задокументировано, ветвь в п.3 issue):** на строках,
где серая зона решается ТОЛЬКО литерой `№` (номер договора как смысл), p2
приходит с канонизированного входа: модель видит `Nо`, а не `№` — семантика <!-- scan-lang:allow -->
токена не тождественна. Расширение словаря = дообучение эмбеддингов, под
квант-политику не проходит (ветвь 2 issue, операторское слово 22.10: «после
релиза по необходимости»).

**Дискриминатор фикса (живой, CI-полка/промер, веса):** `g0133` через
`POST /v1/analyze` — до: `x-guard-cascade2: skipped`; после: обязано стать
`ok` (токенизация канона даёт 0 UNK — промер офлайн на rev 18271032, таблица
в PR). Полный `product_coverage_on_the_whole_golden`: счётчик пропусков 1 → 0,
overlap/exact §10.8 не ухудшается.
