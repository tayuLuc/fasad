# Демон шага 6: границы, заголовки, сеть и чем проверяется

Приложение к [crates/guard-daemon/README.md](../crates/guard-daemon/README.md):
контракт эндпоинтов, режимы хранилища и девиация #55 живут там, здесь — границы
объёма, сетка заголовков и проверка. Ссылки из тестов ведут на явные заголовки
этого файла.

## Заголовки SPEC §8

| Заголовок | На каких ответах | Значение |
| --- | --- | --- |
| `X-Guard-Redacted-Count` | `analyze`, `anonymize`, `deanonymize`, `sessions`-DELETE | число подмен (на `analyze` — найденных спанов, на `deanonymize` — возвращённых токенов); `0` — осмысленный ноль |
| `X-Guard-Max-Risk` | `analyze` | максимальный `score` |
| `X-Guard-Latency-Ms` | все четыре POST/DELETE | миллисекунды, округление вниз |
| `X-Guard-Stage` | все успешные ответы | `cascade-0-only` на шаге 6 |
| `X-Guard-Policy-Applied` | ответ `analyze` | какая политика применена; **наше расширение, вне SPEC §8** |
| `X-Guard-Score-Threshold` | ответ `analyze` | фактически применённый порог; **наше расширение, вне SPEC §8** |
| `X-Session-ID` | запрос (`session`) | id сессии: непустой, ≤ 64 байт, алфавит ASCII-буквы/цифры + `.` `_` `-` |
| `X-Upstream-URL` | — | **шаг 7**, сейчас игнорируется |

Из выходных заголовков SPEC §8 задаёт только `X-Guard-Redacted-Count`,
`X-Guard-Max-Risk` и `X-Guard-Latency-Ms`; входной `X-Guard-Policy` §8 — про
запрос, мы его не отправляем (наш выход называется `-Policy-Applied`, чтобы не
столкнуться). Остальные три — расширения; имена констант в `http.rs` первичны,
таблица обязана с ними совпадать (тест `header_table_in_docs_matches_emitted_names`).

Отсутствие `X-Guard-Redacted-Count` на 2xx клиент обязан считать ошибкой:
мы никогда не подменяем счётчик нулём, если не знаем значения.

## Деградация каскада: почему `cascade-0-only`

1. `guard-onnx` наружу даёт только `arbitrate::DecideArbiter`. LockR-head
   живёт в `crates/guard-onnx/examples/recall_golden.rs` — это харнес, не
   библиотеочный API. Протаскивать его в демона = тащить пример в рантайм,
   поэтому стадия честно называется `cascade-0-only`, а не `full`.
### Что каскад 0 не находит

Следствие для `/v1/analyze`: каскад 0 = валидаторы по цифровым классам.
   **`person_name` не находится никогда** — его ищет токен-классификатор
   (каскад 1+). Класс в схеме есть, в ответе анализа его нет; `/v1/anonymize`
   при этом маскирует имя, если спан прислан клиентом (tray-выделение, каскад
   1+ из другой сборки). Промер этой сессии: `«Ушакова Кира Саввична, ИНН
   2482014338»` → один спан `inn`.
3. Нормализатор каскада 0 не склеивает разделители внутри номера:
   `СНИЛС 65707715421` находится, `СНИЛС 657-077-154 21` — нет (issue #51).
   Это та же причина, по которой гейт #14 меряется на полном каскаде, а не на
   нулевом.
4. Метрика recall (гейт #14, ≥98 % с нижницей Вилсона) измеряется родителем на
   харнесе, не здесь; KNOWN-RED B1 остаётся `#[ignore]`.

## Сеть

Исходящих соединений у демона нет, и это не обещание «на глаз»:

1. HTTP-клиент убран из манифеста crate (он попал туда из скелета шага 3);
2. сетевой гейт дублируется тестом `tests/net_audit.rs` (манифест, скан `src/`,
   `cargo tree -i`) — он бегает в `just test` на обеих ОС; grep-рецепт
   `just net-audit` = локальное convenience (стоит в `just check`), на
   windows-ранах грепа может не быть;
3. листенер loopback — единственная сокет-операция демона: `bind`, не `connect`.

## Профиль риска суррогатов (шаг 7а, #60)

Режим 2 больше не «умирает на второй фамилии»: коллизия слота пула — не отказ
запроса, а типизированная метка `[PERSON_NAME_n_nonce]`, оба имени разворачиваются
byte-exact. Пул вынесен из кода в `data/morph/surrogates.tsv` и расширен с 4 до 128
лемм на корзину; промер на golden-v1 (`pool_probe`): пар разных ФИО в одном слоте
218/351 = 62.1 % → 6/351 = 1.7 %. Остаточные 1.7 % — это метки, не отказы:
деградация измерима счётчиком `Vault::surrogate_fallbacks()`. Числа до/после и
обоснование размера — README демона, §«Хранилище», п. 6.

## Чем это проверяется

| Проверка | Покрывает |
| --- | --- |
| `crates/guard-daemon/src/**` unit (82) | разбор конфига, схема, морфология суррогатов, координаты, валидация спанов, отказ хранилища, оба лимита реестра (FIFO и формы), отказ переанонимизации, откат коллизии слота на метку |
| `tests/net_audit.rs` (3) | сеть: манифест, исходники, дерево зависимостей |
| `tests/wire_e2e.rs` (11) | живой бинарь через сырой HTTP/1.1: round-trip в режиме 3, метки+суррогаты+teardown в режиме 2, 413 в конверте, `400 bad_body` на битом chunked, `400` на `X-Session-ID` вне печатаемого ASCII, `200`+метка на коллизию двух ФИО в одной сессии, `422` на переанонимизацию имени, метки режима 2 и токена режима 3, отказ старта с кодом 2, wall на `0.0.0.0` |
| `just golden-verify`, харнес `recall_golden` | датасет и метрики (родительский замер гейта #14) |
| `guard-vault/examples/pool_probe.rs` | промер пула суррогатов: профиль коллизий до/после на golden-v1 (`probe`), леммы вне нашей морфы (`check`), литералы форм для тестов (`forms`) |
